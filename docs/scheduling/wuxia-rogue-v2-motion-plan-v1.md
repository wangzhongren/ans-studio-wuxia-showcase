# 「纸片人不动」修复 · 程序化动效方案 v1

- 日期：2026-10-31
- 编制：运营（convener）
- 来源任务：幕僚 `#t-mvwenffw-d6a84c72`
- 客户反馈原话：「这个为啥纸片人不动呢，是不是我缺乏什么东西呢，是要制作动画还是说其他的呢。感觉玩起来很奇怪」
- 结论前提：**不需要客户安装任何东西，也不需要再生成美术**；现状是单帧静态贴图只做位置平移与水平翻转，缺少程序化动效。修复以现有 Canvas 绘制与对象池实现。

## 1. 现状核对（运营）

- 输入存在：`src/core/input.js` 与 `src/combat/player.js` 支持 WASD/方向键，玩家有速度、朝向、冲刺、`facingX` 翻转。
- 渲染现状：玩家/怪物/武器贴图只按位置绘制并做水平翻转（`src/combat/auto-attack.js`、`src/monsters/ai.js`）；无走路起伏、攻击挥动、受击后退、生成/死亡姿态等姿态变化，因此观感像静态贴纸。
- 已有可复用能力：`WG.fx.assets` 加载链、受击白闪、击杀碎裂/消散、震屏、`WG.fx.degrade` 降级开关、固定步长循环。
- 共享素材约定：`docs/scheduling/wuxia-rogue-v2-art-render-bridge-v1.md`；模块属主与路径：`docs/proposals/wuxia-rogue-v2-roster-v1.md`。

## 3. 动效参数基线（建议值，允许同量级微调并回报实际值）

所有动画由累计时间 `t`/固定步长 `dt` 推导，不逐帧新建对象、不使用随机对象；动画只影响**绘制变换**，不改移动速度、碰撞、命中判定与数值结算。

| 项 | 基线 |
| --- | --- |
| 玩家移动浮动 | 竖直偏移 ±3 px，周期约 900 ms（sin） |
| 玩家倾斜 | 按水平速度方向约 ±3°，平滑趋近 |
| 玩家待机呼吸 | 竖直 ±1.5 px，周期约 2600 ms |
| 攻击前冲/后坐 | 前冲约 6 px / 60 ms，回收约 120 ms；与自动攻击冷却一致 |
| 武器挥动 | 武器图层绕锚点约 -35°→+35°，120–160 ms；贴图缺失时几何回退不得抖动 |
| 受击后退 | 约 5 px / 90 ms，方向与受击来源相反；白闪保留 |
| 冲刺残影 | 最多 6 个，寿命约 160 ms，alpha 0.35→0；模块级对象池 |
| 脚下影子 | 椭圆：宽 ≈ 实体宽 ×0.55、高 ≈ 实体宽 ×0.18、alpha ≈ 0.25，绘制在贴图之前 |
| 怪物移动摇摆 | 左右/竖直 ±4 px，周期约 700 ms，按 AI 状态区分 |
| 怪物攻击前摇 | 约 250 ms：轻微放大（≈1.06）与后仰，随后扑击位移约 8 px / 100 ms |
| 怪物受击击退 | 约 6 px / 100 ms，白闪保留 |
| 生成弹出 | 缩放 0.6→1.0，约 180 ms ease-out |
| 死亡表现 | 沿用现有碎裂/消散；若无则保持几何淡出，不新增贴图 |

## 4. 降级与性能

- `WG.fx.degrade.enabled` 为真时，关闭残影、生成弹出、装饰性摇摆/浮动等非必要动效；保留位置、朝向、白闪与影子（或按成本一并关闭并回报）。
- 禁止逐帧 `new`、闭包分配、数组扩容；残影/影子使用模块级常量与既有对象池/复用槽位。
- 每帧绘制调用增量有界（残影 ≤6）；不得引入 `setTimeout`/`setInterval` 驱动动画（统一用固定步长）。
- 不得新增全局事件、不得改 `index.html` 脚本顺序、不得联网。

## 7. 近战伤害结算时序修正（2026-10-31 幕僚任务 `#t-mvwf3fn8-2a3e24b7`）

- 起因：怪物动效核对发现近战在 `startAttackAnim` 时立即 `emitHurt`，而前摇 250 ms + 扑击 100 ms 动画随后播放，出现「先掉血、后扑击」的观感，与客户「玩起来奇怪」一致。
- 决定：近战改为**命中帧结算**——前摇只做蓄力/预警，不扣血；扑击到位（约前摇+扑击结束，≈350 ms）时再结算，确保视觉与数值同一帧；攻击资格仍按攻击开始时的距离判定，不在命中帧新增距离规则，避免改变平衡。
- 边界：怪物在命中帧前死亡则取消该次伤害（与对象池归还一致）；击退保持纯视觉偏移；不改数值、AI 目标选择、碰撞与移速；远程箭矢已有碰撞时结算，核对确认不另改。
- 交付方：monsters-director（`src/monsters/`）；若测试断言依赖旧时序，由 core-engine 按新契约更新断言（不得删改有效断言），运营决定是否派发。
- 验收：集成保持 575/0 或更新后全绿；真实浏览器观感由客户确认，运营不代判。
