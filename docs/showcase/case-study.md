# ANS-studio 能力展示：武侠 Roguelike 原型的交付与持续迭代

## 案例定位

江湖夜雨是使用 ANS-studio 开发的桌面浏览器游戏原型。这个案例关注 AI 多角色协作如何形成可运行的软件，并在初次交付之后继续承接功能与体验变更。

最初的需求是武侠题材、大地图、自动攻击、击杀掉落与升级成长，以及后期范围清怪的体验。后续扩展加入开始介绍、结算评分、三个门派、升级三选一与本地模型生成美术。

## 观察到的能力

1. **模块化协作。** 引擎、战斗、怪物、掉落、界面特效、门派和美术有对应属主与边界，契约定义模块间接口。
2. **交付与回归。** 项目包含能从启动走到结算、重开的逻辑检查；历史记录包含重开复位缺陷的返工与独立复验。
3. **持续迭代。** 后续反馈涉及玩法扩展、素材替换、持械图层、透明升级弹层、程序化动效和近战伤害时序，并被拆分为对应模块任务。
4. **证据与表述校正。** 验收发现某生成素材未被运行时引用后，交付口径修正为“17 项生成、16 项引用、1 项保留”。

## 时间与来源

时间使用 2026-10-31 北京时间（UTC+8）。[timeline.json](timeline.json) 摘录本机执行日志的事件时间、任务编号和部分交付文档的文件时间，逐项标记来源类型。

需求首任务为 14:17:31；基础版返工复验报告为 15:32:57，相差 **1 小时 15 分 26 秒**。基础版运行基线固定于 14:31:10，从该时点至上述复验报告约 **1 小时 1 分 47 秒**。

公开时间线的最后一项为 21:14:34 的怪物近战伤害时序修正报告，从首任务算起约 **6 小时 57 分钟**。这是选定记录区间，不代表所有角色最终验收完成，也不意味着开发在该时点结束。

时间跨度包含沟通、等待与返工。扩展过程中曾遇到旧 run pin 无法派发新角色的问题，随后通过建立新流程线推进；这类流程开销也属于案例事实。

原始 `.ans/` 会话与审计日志未公开。本仓库提供精简事件摘录、项目文档与可复跑的测试，供读者核查；公开摘录不是独立第三方审计或不可篡改证明。交付文档的文件时间只作为辅助时间点。

## 发布整理时的验证

[test-results.json](test-results.json) 记录本次复跑命令、退出码与输出；全部 7 组断言测试通过，另有 Node 纯逻辑基准通过。集成测试为 575 项通过。

这些检查验证特定逻辑与模拟环境下的流程。历史验收文档要求的真实浏览器目视项目及真实 FPS，并未因本次命令行复跑自动获得通过；最后一轮动效修正也不应仅凭旧质检报告宣称已完成独立视觉验收。

## 可以支持的结论

此案例展示了 ANS-studio 组织多角色交付一个具有完整单局循环的游戏原型，并持续推进后续需求与缺陷修复的能力。读者可直接运行代码，检查模块边界与测试，并沿文档观察迭代过程。

本次未核算完整 token 总量、模型费用、人工介入工时，也未安排单代理或其他工具的同条件对照，因此不据此宣称具体加速倍数、成本优势、全自动开发或商业游戏品质。
