# 产品意图：武侠大地图 Roguelike（wuxia-rogue）

## 1. 客户原话（2026-10-31，原文记录）

> 「给我做一个武侠rouge 游戏吧，不要做成卡牌，要在一个大地图里面，自动攻击附近的怪物，然后收集掉落物，升级。如果运行好，后面应该满屏清怪的那种爽感。」

关键澄清（来自派发说明，视为客户已确认的补充判读）：

1. 类型为武侠题材 Roguelike（肉鸽），明确「不做卡牌」——战斗与构筑不走抽牌/出牌，走即时动作与数值成长。
2. 场景为一张较大的大地图，可移动探索；角色自动攻击附近怪物，玩家操作以移动/走位/闪避为主。
3. 核心循环：击杀怪物 → 掉落物品 → 拾取收集 → 升级/成长。
4. 爽感目标：成长到后期出现「满屏清怪」的爽感（范围伤害、怪潮、视觉反馈）。
5. 平台形态：默认按「桌面端可运行原型」理解，具体技术栈留给策划阶段。

## 2. 目标用户与场景

- **目标用户**：喜欢即时动作 + 刷怪成长类 Roguelike（如幸存者类玩法）的玩家，以及需要用短时间获得成长爽感的休闲玩家。
- **使用场景**：单人在 PC 上开一局（几分钟到十几分钟），在大地图里边走边打、边捡边变强，越到后期越爽。
- **不使用场景**：不面向卡牌构筑玩家；不面向需要联机、剧情叙事或长期养成的玩家。

## 3. 要解决的问题

1. 明确玩法方向：把「武侠 + 大地图 + 自动攻击 + 掉落升级 + 后期清屏」做成一个能被直接体验的原型，避免团队误入卡牌路线。
2. 建立可验证的核心循环闭环：击杀、掉落、拾取、成长四步在单局内真实生效并互相驱动。
3. 把「爽感」这种主观描述转成可观察的后期表现（怪物密度提升 + 范围清怪 + 明确的视觉/音效反馈）。

## 4. 范围（Scope）

**做（in scope）**

- S1 大地图：一张明显大于单屏、可自由移动探索的地图，玩家可在地图内移动走位。
- S2 自动攻击：角色对附近一定范围内的怪物自动发起攻击，无需手动点选目标；玩家操作以移动/走位/闪避为主。
- S3 怪物与击杀：地图上持续存在怪物，可被击杀并产生死亡反馈。
- S4 掉落与拾取：怪物击杀后掉落物品，物品可被角色拾取并进入持有/结算。
- S5 成长：拾取与击杀带来升级或属性/能力成长，成长需在单局内可感知（角色明显变强）。
- S6 后期爽感：随成长推进，怪物数量/威胁上升，角色具备范围清怪能力，出现「满屏清怪」的观感（含视觉反馈）。
- S7 单局流程：开始一局 → 探索战斗成长 → 达成后期清屏体验 → 单局结束（胜负/结算规则由策划细化，但必须有明确结束条件）。
- S8 桌面端可运行原型：可在 PC 上启动、游玩、验收。

**明确不做（out of scope，见第 6 节非目标）**

- 不做卡牌：**不包含抽牌、出牌、手牌/牌组、卡牌构筑**等任何卡牌机制；成长与战斗不走卡牌路线。

## 5. 验收标准（可判定）

> 每条都要求「可执行的操作 + 可观察的结果」，不依赖主观形容词。

- **AC-1 地图可移动**：启动原型后可进入大地图；使用移动键/摇杆操作，角色位置连续变化；地图可视范围明显大于一屏（移动可看到新区域），且角色不能被地图边界卡死。
- **AC-2 自动攻击生效**：当怪物进入角色攻击范围时，无需玩家额外操作即自动产生攻击；怪物受到伤害（血量下降），攻击有可见的表现（特效/受击反馈）。离开范围后不再自动攻击。
- **AC-3 击杀与掉落**：怪物血量归零后死亡消失；死亡位置产生可拾取的掉落物，掉落物在地图上可见。
- **AC-4 拾取生效**：角色移动到掉落物位置（或触发拾取范围）后，掉落物消失并计入玩家持有/资源；拾取数量可核对（例如计数或背包/资源数值变化）。
- **AC-5 升级/成长生效**：获得足够经验或资源后角色升级；升级带来可观察的属性或能力提升（如攻击力、攻击范围、攻击频率、生命值等数值变化，且该变化可在游戏内或界面中核对）。
- **AC-6 后期清怪表现**：在单局持续推进后，同屏怪物密度显著高于开局；角色具备范围伤害/多重攻击能力，可一次性清理多只怪物；该过程有明确的视觉反馈（伤害数字、特效、怪物成片消失等），呈现「满屏清怪」的观感。
- **AC-7 非卡牌判定**：完整游玩流程中，界面与操作不存在抽牌、出牌、手牌区、牌组构筑等卡牌元素；战斗与成长完全由即时操作与数值成长驱动。
- **AC-8 可运行与可复现**：原型在桌面端可正常启动并完成至少一局完整流程；按同样的操作路径可重复触发上述 AC-1 ~ AC-6 的现象；后期怪潮场景下仍保持可玩帧率（不出现持续卡死或不可操作）。

## 6. 非目标（Non-Goals）

- 不做卡牌玩法（抽牌/出牌/牌组构筑）——这是硬性排除项。
- 不做联机/多人、排行榜、账号与存档云同步。
- 不做商业化、内购、广告。
- 不做完整剧情、任务线、角色养成与长期 meta 进度（后续版本再议）。
- 不做移动端、主机端、手柄深度适配（桌面键鼠优先）。
- 不在本环节确定引擎、技术架构、美术风格、人员分工。

## 7. 约束（Constraints）

- **平台**：桌面端单机可运行原型（Windows 优先）；引擎/技术栈由策划阶段决定，本意图不做技术选型。
- **操作模型**：玩家核心操作是移动/走位/闪避；攻击自动触发，不要求手动瞄准或点选目标。
- **节奏**：成长必须在单局内可感知（一局内能明显变强并进入清屏阶段），不能把爽感推到多局之后。
- **性能**：后期大量怪物同屏时仍需保持可玩帧率，不能因清屏特效导致卡死。
- **合规与内容**：武侠题材，无现实敏感内容；不引入第三方版权素材（素材来源由后续环节确定）。
- **范围纪律**：任何卡牌相关机制一律不进入范围；需求变更需走新版本意图文档（v2/v3…），不原地修改本文件。

## 8. 质量档位

- 定位为**可玩原型（Prototype）**：优先保证核心循环闭环与爽感可体验，允许美术与音效为占位级；但 AC-1 ~ AC-8 必须真实可判定地满足。
- 不以商业发行质量（美术精度、剧情、数值平衡深度）作为本版验收前提。

## 9. 本环节不产出

策划方案、系统数值设计、关卡与怪物设计、技术架构、人员名单与排期——均属后续环节，本文件只锁定产品意图与可验收边界。
