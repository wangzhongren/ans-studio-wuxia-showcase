# 产品意图：武侠大地图 Roguelike（wuxia-rogue-v2）

## 0. 来源与版本说明

- **来源**：本文件是**已批准需求变更 `req-36c38669f1d06b83`** 在新流程线 `wuxia-rogue-v2` 上的**重述**。
- **目的**：旧流程线 `wuxia-rogue` 的 run 基线无法刷新（应用固定核对 v1 规范物证，任何角色均无改写 run pin 的工具），新增角色 `sect-designer`、`art-generator` 无法派发；故按**同一已批准范围**新开流程线，使应用重新生成运行基线。
- **范围纪律**：**不扩大范围**。本文件完整继承原 v1（S1~S8、AC-1~AC-8）与已批准变更 v2（S9~S13、AC-9~AC-13）的全部内容；代码与素材仍写在同一个项目里，不重做游戏范围。
- **自足性**：本流程线不依赖旧文档即可验收；正文重复给出完整 S/AC 清单。

## 1. 客户原话记录

**v1 原始需求（2026-10-31）**：

> 「给我做一个武侠rouge 游戏吧，不要做成卡牌，要在一个大地图里面，自动攻击附近的怪物，然后收集掉落物，升级。如果运行好，后面应该满屏清怪的那种爽感。」

**v2 变更需求（2026-10-31）**：

> 「这个还是有问题的，首先怎么没有怎么开始游戏的介绍页面，其次也没有游戏结束的几分画面。其次升级怎么没有一个技能选择呢，开局应该可以选择几个门牌啊，还有就是游戏素材，应该用我电脑本地的 image2.5 模型来生成啊。」

**客户补充（2026-10-31）**：

> 「HF 缓存里有 Qwen-Image-2.1 这个模型」

**门派与素材口径（来自已批准变更说明，非客户逐字原话）**：

- 开局门派示例：**剑宗偏攻速、刀门偏爆发、医谷偏生存/回复**（3 个门派，可等价命名）。
- 素材模型：**Qwen-Image-2.1**（客户口述的 "image2.5" 以 HF 缓存中的 Qwen-Image-2.1 为准）。

## 2. 目标用户与场景

- **目标用户**：喜欢即时动作 + 刷怪成长类 Roguelike（如幸存者类玩法）的玩家，以及希望短时间获得成长爽感的休闲玩家。
- **使用场景**：单人在 PC 上开一局（几分钟到十几分钟）；打开先看介绍页 → 选门派 → 大地图里边走边打、边捡边变强 → 升级时做成长选择 → 后期清屏 → 结算评分 → 再来一局。
- **不使用场景**：不面向卡牌构筑玩家；不面向需要联机、剧情叙事或长期养成的玩家。

## 3. 要解决的问题

1. 明确玩法方向：把「武侠 + 大地图 + 自动攻击 + 掉落升级 + 后期清屏」做成可直接体验的原型，避免误入卡牌路线。
2. 建立并验证核心循环闭环：击杀、掉落、拾取、升级四步在单局内真实生效、互相驱动。
3. 把「爽感」转成可观察的后期表现：怪物密度提升 + 范围清怪 + 明确视觉反馈。
4. 补齐体验闭环：开始介绍页、结算评分页、开局门派选择、升级三选一，让玩家知道怎么开始、怎么变强、这局打得如何。
5. 用本地模型生成美术替换程序化占位，同时保证运行时零模型依赖、可离线运行。

## 4. 范围（Scope）

### 4.1 基础玩法（继承自 v1，继续有效）

- **S1 大地图**：一张明显大于单屏、可自由移动探索的地图，玩家可在地图内移动走位。
- **S2 自动攻击**：角色对附近一定范围内的怪物自动发起攻击，无需手动点选目标；玩家操作以移动/走位/闪避为主。
- **S3 怪物与击杀**：地图上持续存在怪物，可被击杀并产生死亡反馈。
- **S4 掉落与拾取**：怪物击杀后掉落物品，物品可被角色拾取并进入持有/结算。
- **S5 成长**：拾取与击杀带来升级或属性/能力成长，成长需在单局内可感知（角色明显变强）。**获得方式由 S12 的升级三选一承载**。
- **S6 后期爽感**：随成长推进，怪物数量/威胁上升，角色具备范围清怪能力，出现「满屏清怪」的观感（含视觉反馈）。
- **S7 单局流程**：开始一局 → 探索战斗成长 → 达成后期清屏体验 → 单局结束（胜负/结算规则由策划细化，但必须有明确结束条件）。
- **S8 桌面端可运行原型**：可在 PC 上启动、游玩、验收。

### 4.2 变更新增（已批准 req-36c38669f1d06b83）

- **S9 开始界面（标题/介绍页）**：进入游戏先看到独立开始页，包含游戏名、玩法说明（目标、操作方式、核心循环：击杀→掉落→拾取→升级）、醒目的「开始游戏」入口；不能只是一行小字或直接进入战斗。
- **S10 结算评分页**：一局结束（死亡或通关）后展示完整战绩：存活时间、等级、击杀数、拾取数、银两、最终攻击力；给出评分（如 S/A/B/C）；提供「再来一局」入口；结算数据与本局实际数值一致。
- **S11 开局门派选择**：开始游戏前从 3 个门派中选择（建议：剑宗偏攻速、刀门偏爆发、医谷偏生存/回复）；不同门派有可观察的初始属性差异与专属成长方向；选择结果影响本局。
- **S12 升级三选一（非卡牌）**：角色升级时弹出成长/技能选择面板，提供 3 个选项供玩家选择其一；选择后立即生效并影响后续战斗；替代 v1 的全自动成长；**不是抽牌/手牌/牌组/回合制**，样式可用卷轴/石碑等非卡牌表达。
- **S13 本地素材生成与替换**：使用客户本机 HF 缓存的 Qwen-Image-2.1 生成游戏美术（标题背景、角色、怪物、UI 素材等），替换程序化占位；生成物以 PNG/WebP 放入项目 `assets/` 并由游戏引用；运行时游戏不得联网、不得加载模型、不得依赖任何生成环境，仍可零依赖双击运行；未能生成成功的素材允许保留程序化占位并如实记录。

### 4.3 明确不做（out of scope）

- **不做卡牌**：不包含抽牌、出牌、手牌/牌组、卡牌构筑、卡牌收集、回合制卡牌对战等任何卡牌机制；成长与战斗不走卡牌路线。

## 5. 验收标准（可判定）

> 每条都要求「可执行的操作 + 可观察的结果」，不依赖主观形容词。
> **通用验收方式**：AC-1 ~ AC-13 均需在真实浏览器/真实运行环境中人工目视验收，配合实际操作复现；仅凭截图、自述或日志不得判定通过。

### 5.1 基础玩法验收（AC-1 ~ AC-8）

- **AC-1 地图可移动**：启动原型后可进入大地图；使用移动操作，角色位置连续变化；地图可视范围明显大于一屏（移动可看到新区域），且角色不能被地图边界卡死。
- **AC-2 自动攻击生效**：当怪物进入角色攻击范围时，无需玩家额外操作即自动产生攻击；怪物受到伤害（血量下降），攻击有可见的表现（特效/受击反馈）。离开范围后不再自动攻击。
- **AC-3 击杀与掉落**：怪物血量归零后死亡消失；死亡位置产生可拾取的掉落物，掉落物在地图上可见。
- **AC-4 拾取生效**：角色移动到掉落物位置（或触发拾取范围）后，掉落物消失并计入玩家持有/资源；拾取数量可核对（例如计数或背包/资源数值变化）。
- **AC-5 升级/成长生效**：获得足够经验或资源后角色升级；升级带来可观察的属性或能力提升（如攻击力、攻击范围、攻击频率、生命值等数值变化，且该变化可在游戏内或界面中核对）。
- **AC-6 后期清怪表现**：在单局持续推进后，同屏怪物密度显著高于开局；角色具备范围伤害/多重攻击能力，可一次性清理多只怪物；该过程有明确的视觉反馈（伤害数字、特效、怪物成片消失等），呈现「满屏清怪」的观感。
- **AC-7 非卡牌判定**：完整游玩流程中，界面与操作不存在抽牌、出牌、手牌区、牌组构筑等卡牌元素；战斗与成长完全由即时操作与数值成长驱动。
- **AC-8 可运行与可复现**：原型在桌面端可正常启动并完成至少一局完整流程；按同样的操作路径可重复触发上述 AC-1 ~ AC-6 的现象；后期怪潮场景下仍保持可玩帧率（不出现持续卡死或不可操作）。

### 5.2 变更新增验收（AC-9 ~ AC-13）

- **AC-9 开始介绍页**
  判定：启动游戏后首先出现独立开始页，而非直接进入战斗；页面上可辨认地包含：①游戏名；②玩法说明（目标、操作方式、核心循环）；③醒目的「开始游戏」入口。点击「开始游戏」后进入门派选择/战斗流程。玩法说明不能只是一行小字（需构成可阅读的介绍区域）。

- **AC-10 结算评分页**
  判定：一局结束（死亡或通关）后自动进入结算页，无需玩家手动打开；页面上可辨认地展示：存活时间、等级、击杀数、拾取数、银两、最终攻击力，以及评分（S/A/B/C 之一）；存在「再来一局」入口且点击后能开启新一局。结算页上的各数值与本局过程中的实际统计一致（抽查至少等级、击杀数、存活时间三项对得上）。

- **AC-11 开局门派选择**
  判定：开始游戏后、进入战斗前，出现门派选择界面，至少 3 个门派可选（含剑宗、刀门、医谷或等价命名）；每个门派有说明其定位/初始属性/成长方向；选择不同门派进入游戏后，角色初始属性或成长表现存在可观察差异（例如攻速、攻击力、生命/回复中至少一项不同），且该差异可核对。

- **AC-12 升级三选一（非卡牌）**
  判定：角色升级时出现选择面板，恰好提供 3 个可辨识的成长/技能选项；玩家可选择其一，选择后效果立即生效，并可在后续战斗/属性中观察到变化（例如攻击范围、伤害、攻速、生命等）；下一次升级再次提供 3 个选项；面板在未选择前不自动替玩家选择（或明确可暂停选择）。
  **非卡牌判定口径**（必须同时满足）：
  1. 不存在抽牌、牌堆、手牌区、弃牌堆、牌组构筑、卡牌收集等元素；
  2. 选项在升级时即时出现，选择后即消耗/消失，不跨局收集、不进入卡组；
  3. 不存在回合制卡牌对战；战斗仍是即时自动攻击 + 走位的 v1 模式；
  4. 视觉表达采用卷轴/石碑/技能光球等非卡牌样式即可，不必是卡牌。

- **AC-13 本地素材替换且运行时零依赖**
  判定：①游戏运行中展示的标题背景、角色、怪物及主要 UI 素材为 Qwen-Image-2.1 生成的美术文件，而非纯程序化色块/占位（允许少量元素保留占位，但必须如实记录）；②生成物以 PNG/WebP 形式存在于项目 `assets/` 内并被游戏实际引用，可在目录与文件中核对；③断网状态下启动并游玩，游戏正常运行，不加载模型、不访问网络、不依赖 Python/生成环境；④素材生成记录可核对（哪些素材由 Qwen-Image-2.1 生成、哪些失败后保留占位），不得虚报成功；⑤在真实浏览器中目视确认替换后的观感与程序化占位有可辨识的差异。

- **验收方式**：AC-9 ~ AC-13 需真实浏览器目视验收，不接受截图造假或口头自述。

## 8. 质量档位

- 定位为**可玩原型（Prototype）**，且要求「体验闭环完整」：开始 → 选门派 → 战斗 → 升级选择 → 结算 → 再来一局的路径必须走得通、看得懂。
