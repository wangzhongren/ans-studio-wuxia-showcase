# 江湖夜雨 · ANS-studio 能力展示

一个使用 [ANS-studio](https://github.com/wangzhongren/ans-studio) 开发并持续迭代的武侠 Roguelike 游戏原型。

本仓库展示 ANS-studio 如何组织多个 AI 角色，完成需求梳理、模块实现、集成测试、缺陷返工与需求变更。游戏代码、生成美术、角色卡、架构契约和阶段验收文档一并公开，便于体验与核查。

**约 75 分钟完成基础原型及自动化逻辑复验；在约 7 小时的项目时间跨度内，继续推进门派、升级三选一、本地 AI 美术接入及多轮体验修正。** 时间来自本次项目的执行记录，不是性能承诺或与其他工具的对照实验。

## 直接运行

下载本仓库并解压，使用桌面浏览器打开 `index.html`。Windows 也可以双击 `run.cmd`。

运行游戏无需安装 Node.js、Python 或生成模型。仓库已包含运行所需的本地素材，无需构建。

如果浏览器对本地文件有限制，可在项目目录运行：

```sh
python -m http.server 8000
```

然后访问 <http://localhost:8000/>。

## 游戏内容与操作

- 大于单屏的地图、角色走位与附近敌人的自动攻击。
- 击杀 → 掉落 → 拾取 → 升级 → 能力成长的单局循环。
- 剑宗、刀门、医谷三个门派，以及升级三选一。
- 怪潮、范围攻击、伤害数字、受击与击杀反馈。
- 开始介绍、门派选择、胜负结算、战绩评分与重新开局。
- 本地生成美术及加载失败时的占位回退。

| 操作 | 按键 |
| --- | --- |
| 移动 | WASD / 方向键 |
| 闪身 | Shift / 空格 |
| 确认菜单选项 | Enter / 鼠标点击 |
| 结算后重开 | R |
| 性能信息 | F3 |
| 调试：快进到 5 分 30 秒 | F4 |
| 调试：生成一波怪潮 | F5 |

## 这个案例展示了什么

**多角色协作交付。** 核心引擎、战斗、怪物、掉落成长、界面特效、门派和美术流水线由对应角色负责，依据模块契约集成。

**承接后续需求。** 基础原型之后继续增加门派、升级选择、生成美术，并根据反馈调整透明弹层、持械效果、角色与怪物动效，以及近战视觉和伤害时序。

**以证据推动返工。** 记录中包含重开复位缺陷的发现与复验，也包含对“17 项素材全部接入”表述的纠正：实际为 17 项生成、16 项运行时引用、1 项保留不用。

这是一项真实项目案例。它支持对交付与持续迭代能力的观察；并发加速比例、总 token 成本和相对其他工具的效率优势，需要额外的计量与对照。

## 测试

自动化检查需要本机安装 Node.js，下面的测试不需要安装 npm 依赖：

```sh
node tests/smoke-core.js
node tests/integration-check.js --failures
node tests/loop-check.js
node tests/background-check.js
node tests/perf-check.js
node tests/perf-integration-check.js
node src/sects/self-check.js
node tests/bench.js
```

发布整理时复跑结果：核心 **76**、集成 **575**、循环 **15**、背景 **31**、性能工具 **52**、性能集成 **16**、门派 **137** 项通过，均为 0 失败；Node 逻辑基准通过。执行输出见 [本次测试记录](docs/showcase/test-results.json)。

上述检查包含 fake DOM 与纯逻辑测试。它们不等同于浏览器实玩、视觉验收或浏览器 FPS 证明。项目仍为持续迭代中的原型；历史质检报告保留各自阶段的发现与限制。

## 代码与过程材料

| 路径 | 内容 |
| --- | --- |
| `src/core/` | 配置、输入、循环、事件、对象池、空间索引与游戏装配 |
| `src/combat/`、`src/monsters/` | 玩家战斗、怪物 AI 与怪潮 |
| `src/loot/`、`src/sects/` | 掉落、成长、门派与升级选择 |
| `src/ui/`、`src/fx/`、`styles/` | 界面、HUD、渲染反馈与样式 |
| `assets/` | 运行素材、程序化占位与来源清单 |
| `tests/` | 集成、回归与基准检查 |
| `角色卡/` | 项目角色职责与修改边界 |
| `docs/` | 需求、方案、契约、调度、验收与案例材料 |
| `tools/art/` | 可选的本地美术生成工具与提示词 |

游戏使用原生 JavaScript、Canvas 2D 与 CSS。美术生成流程记录使用本机 Qwen-Image-2.1；成品素材与来源见 [SOURCES](assets/generated/SOURCES.md)，生成工具见 [美术流水线说明](tools/art/README.md)。生成环境与游戏运行环境相互独立。

本仓库不包含本机 ANS 原始会话日志、Python 虚拟环境、模型权重与原始出图。历史文档中的本机路径用于记录当时环境，运行游戏无需复制这些路径或配置。
